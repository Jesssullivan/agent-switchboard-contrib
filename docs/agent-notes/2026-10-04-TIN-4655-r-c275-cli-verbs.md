## Verbs

| Verb | Request | Needs |
| --- | --- | --- |
| `swb send <to> <ticket> [--ruling ID] [--operator-directed] [--in-reply-to ULID] [--thread ULID] [--msg-id ULID] < body` | `POST /v1/send` | `SWB_BROKER_URL`, `SWB_AGENT_ID` |
| `swb ack <msg_id>` | `POST /v1/ack` | `SWB_BROKER_URL`, `SWB_AGENT_ID` |
| `swb peers` | `GET /v1/peers` (no `me`: read-only, refreshes no lease) | `SWB_BROKER_URL` |
| `swb doctor [--register]` | `GET /v1/peers`, optional `GET /metrics`, optional `POST /v1/register` | nothing; it reports what is missing |

- The `send` body is read from stdin, bounded to 16 KiB and required to be
  UTF-8. It never comes from argv, so it stays out of the process table and
  never passes through a shell.
- Recipient, ticket, ULIDs and `--operator-directed` (which requires
  `--ruling`) are checked locally the same way swb-store checks them. The
  broker still re-checks everything.
- Exit codes follow the existing CLI: 0 success, 2 usage, 3 runtime or broker
  failure. `doctor` exits 3 if any check fails.
- A non-2xx broker reply now reads `broker HTTP <status>: <error>`. The
  error text is truncated to one printable line of at most 200 characters.

## doctor

Checks run in order, and each prints `ok`, `skip` or `FAIL` with a `fix:`
line:

1. `SWB_BROKER_URL` is set and has the `http://host:port` form.
2. Identity: `SWB_HARNESS`, `SWB_HOST`, `SWB_SESSION_PID`, `SWB_PROC_START`
   and `SWB_SESSION_ID` are present and valid. It prints the agent id that
   `register` would mint. The fix text points at the R-C273 launcher
   exports and says never to walk process ancestry (R-N11).
3. `SWB_AGENT_ID`, if set, is well formed and equals the derived identity.
4. Broker REST is reachable: `GET /v1/peers` returns a peers list.
5. `/metrics` is checked only when `SWB_METRICS_URL` is set, because metrics
   listen on a separate port that the client cannot infer.
6. Register: **dry by default.** The broker has no dry-run register, so the
   dry mode validates the exact payload locally and makes no request.
   `--register` performs the real round trip, an upsert of this session's
   own row, and checks that the returned `agent_id` matches.

`SWB_METRICS_URL` is new and optional, read only by `doctor`.

## Tests

Twelve new tests in `crates/swb/src/main.rs`. They inject `SWB_*` through a
closure (`Lookup`), so they never mutate process environment and cannot
race the one existing env-owning test. Loopback mock brokers assert the
method, path and JSON for each verb, and that a dry-run doctor makes exactly
one request (`GET /v1/peers`) and never registers.

Sting receipts (`~/scratch/swb-cli-verbs`, `tinyland-heavy`, `nix develop`):
- `cargo test -p swb`: 16 passed.
- `cargo clippy -p swb --all-targets -- -D warnings`: clean.
- `cargo fmt --all` was applied.
- `just check` (Bazel, `--lockfile_mode=error`): 8 of 8 test targets pass.
  The lock files are byte-identical to upstream main.
