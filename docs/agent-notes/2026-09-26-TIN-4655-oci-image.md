## Mutation receipt

- SWB-R04 and R-N13: `//deploy:image` layers the Bazel-built `swb` binary over
  the pinned `gcr.io/distroless/cc-debian13:nonroot` Linux/amd64 manifest.
  Its entrypoint is `/usr/local/bin/swb` with default command `serve`.
- SWB-R04 and R-N13: `//deploy:image.digest` emits the exact OCI manifest
  digest. `//deploy:push` is an explicit digest-first, tagless GHCR publisher;
  the PR and CI do not invoke it. A reviewer can run `just image` on the
  Linux/amd64 build host to obtain the future blahaj image reference.
- R-N13: the module dependency was added with the repository's `just lock`
  lane on honey. The remote scratch copy excludes `.git`; the recipe's final
  `git status` fails after all three lock-generation commands complete. The
  generated lock set was copied back together. `Cargo.lock` and
  `cargo-bazel-lock.json` remain byte-identical; `MODULE.bazel.lock` gains the
  rules_oci dependency graph checksums.

## Honey verification

- The first `just image` build passed, but its binary required `GLIBC_2.39`
  while the Debian 12 base provided an older libc. That candidate was not
  runnable and was never published. The corrected image uses a pinned Debian
  13 base; the exact candidate digest stays in Bazel's generated image.digest
  and the PR check output, not in this public note.
- The image config reports `linux/amd64`, `User: 65532`, entrypoint
  `/usr/local/bin/swb` and default command `serve`.
- `readelf` found four dynamic runtime dependencies; image layer listings
  contain `libgcc_s.so.1`, `libm.so.6`, `libc.so.6`, and
  `ld-linux-x86-64.so.2`, as well as `/usr/local/bin/swb`.
- `just check` passed all eight Bazel check targets on honey. Neo compiled
  nothing.

## 2026-09-27 correction (SWB-R04, R-N12, R-N13)

The first candidate's Debian 12 libc was too old for the Honey-built binary.
After the operator approved a materially different response to the earlier
guard refusal, the image base moved to a pinned Debian 13 nonroot manifest.
The package targets now require both Linux and x86_64. Honey rebuilt the
image, and a rootless Podman run of `swb version` from that exact OCI layout
exited 0. Bazel rejected explicit Linux/aarch64 and macOS/x86_64 image builds
as incompatible. The exact corrected digest is retained in the generated
`image.digest` output and PR check output.

## Delivery boundary

No registry push or deployment was performed. The actual tailnet Host-header
allowlist, writable PVC ownership for UID 65532, and live rollout belong to
the blahaj owner. The source keeps `SWB_MCP_ALLOWED_HOSTS` explicit.
