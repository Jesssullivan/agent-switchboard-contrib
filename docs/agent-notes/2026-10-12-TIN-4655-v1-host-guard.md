# Host and Origin guard on every main-listener route

## Finding

Lab's review of blahaj#2087 (review 5496989719 on `xoxd-ai/blahaj`, TIN-5770
comment `e503f591`): in v0.2.1 (`f29769b3`, image source `9bc96349`, digest
`sha256:2d53153f…`) the Host allowlist reached only `/mcp`, through rmcp's
own check. `/v1/register`, `/v1/end`, `/v1/peers`, `/v1/send`, `/v1/inbox`
and `/v1/ack` accepted any `Host`. A DNS-rebinding page in a seat's browser
could register, send, read an inbox, ack or end as any identity. Messages
were still stamped `authority: peer`.

## Change

- `RequestGuard` in `crates/swb-broker/src/lib.rs` is one axum middleware
  layer over the whole main listener, applied after `extra` is merged, so
  the `test-clock` route and the 404 fallback are covered too.
- Host rules mirror rmcp's `/mcp` check (same `SWB_MCP_ALLOWED_HOSTS` list;
  a host entry without a port admits any port; HTTP/2 `:authority` fallback)
  and add: missing Host is refused, duplicate Host is refused, userinfo is
  refused, and an empty allowlist refuses to start.
- Origin: refused when present and not on `SWB_ALLOWED_ORIGINS` (default
  empty). All real clients are non-browser and send no Origin.
- Review hardening (two independent adversarial reviews of #28, neither
  refuted): a bracketed Host must be an IPv6 literal, a `:` must carry a
  valid port, and an absolute-form target's authority must be allowed too.
  None of these was reachable from a browser.
- Correction: the first draft said the empty-Origin default refuses every
  browser-originated request. It does not: browsers omit `Origin` on simple
  GETs, and `GET /v1/peers` and `GET /v1/inbox` change state. ADR-0001 now
  records that cross-site GET residual and the follow-up.
- Every refusal is 403 with a JSON `error`, before any handler runs.
- `/metrics` (separate listener, aggregate counters only, scraped by pod
  address) is deliberately unguarded; a test pins that.

## Tests

`crates/swb-broker/src/lib.rs` tests: rebinding Host (`attacker.example`,
with and without port, suffix trick, userinfo, empty) refused on all six
`/v1` routes and `/mcp` with store state unchanged; missing and duplicate
Host refused on every route; allowed hosts with and without port, uppercase
and `[::1]:8080` accepted; a `host:port` entry admits only that port;
Origin refused unless allowlisted, with scheme and port matched; unknown
paths guarded and metrics not; empty or invalid allowlists refused; the
test-clock route is behind the guard; malformed ports, bracketed non-IPv6
hosts and a disallowed absolute-form authority are refused.

## Release

The approved release stays v0.2.1 (SWB-R58). A v0.2.2 image carrying this
fix needs its own release ruling, two matching clean builds and an
`approved-broker.json` update before `release.yml` will publish it.
